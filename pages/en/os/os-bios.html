BIOS: The Original Firmware.

How BIOS Worked

When you pressed the power button on any PC from 1981 through the mid-2000s, the first thing that ran was the BIOS. Stored on a small ROM chip soldered to the motherboard, the BIOS was completely independent of any operating system or hard drive. It could run even with no storage connected at all.

The boot sequence was always the same. First, the BIOS performed the POST — Power-On Self Test — checking that RAM was present and functional, that the CPU was operating correctly, and that essential hardware was detected. A successful POST produced a single beep on most systems. Failed hardware produced specific beep codes that technicians could use to diagnose problems without a screen.

After POST, the BIOS searched for a bootable device in the configured order — typically floppy drive first, then hard drive, then CD-ROM as optical drives became common. It read the first sector of the bootable device (the Master Boot Record or MBR) and handed control to whatever boot code it found there. From that point, the operating system took over.

The BIOS setup utility was accessed by pressing a specific key during the brief window after POST. Once inside, users could configure the boot order, set the system date and time, control CPU and memory settings, enable or disable integrated peripherals, and set passwords. Despite its importance, the interface was entirely keyboard-driven and looked identical whether you were using a $500 budget machine or a $5,000 workstation.

Why BIOS Had to Die

The original IBM PC BIOS was written in 16-bit real mode — the operating mode of the Intel 8088 processor from 1981. Every BIOS chip shipped for the next 25 years maintained compatibility with this 1981 standard. This backward compatibility was both BIOS's greatest strength and its fatal weakness.

The most visible limitation was the MBR partition scheme. The Master Boot Record could only describe partitions up to 2 TB in size and could only support four primary partitions. As hard drives grew beyond 2 TB and users needed more flexible partitioning, this became a serious constraint.

The BIOS also had no understanding of networking, no graphical capability, no mouse support, and no way to boot from USB drives without special workarounds. Security features were primitive — the boot process had no way to verify that the bootloader had not been tampered with. Rootkits could embed themselves in the MBR and be virtually undetectable.

Perhaps most significantly, the BIOS was 16-bit code running on 64-bit hardware. Modern CPUs had to temporarily drop into a legacy compatibility mode just to run the BIOS — a process that added time and complexity to every boot. By the mid-2000s, Intel had developed a replacement.

UEFI: The Modern Replacement

UEFI — Unified Extensible Firmware Interface

UEFI (Unified Extensible Firmware Interface) began as EFI, developed by Intel in the late 1990s for their Itanium server processors. The Itanium was a 64-bit architecture completely incompatible with the 16-bit BIOS, making a new firmware standard necessary. EFI became UEFI in 2005 when it was transferred to the UEFI Forum — a consortium including Intel, AMD, Microsoft, Apple, and major PC manufacturers.

UEFI is fundamentally different from BIOS in architecture. It is a complete mini-operating system in its own right — written in C, capable of running network drivers, accessing the internet before the OS loads, supporting a graphical mouse-driven interface, and loading 64-bit code natively. The UEFI specification defines a standard API that operating systems use to interact with hardware during boot, replacing the ad-hoc BIOS calls that OS developers had to work around for decades.

The most visible change for users is the UEFI setup interface. Modern UEFI implementations from ASUS, MSI, Gigabyte, and others feature full graphical interfaces with mouse support, fan curve editors, RGB lighting controls, and detailed hardware monitoring — all running before any operating system loads.

GPT and Secure Boot

UEFI introduced two critical technologies alongside the new firmware architecture. The first is GPT — GUID Partition Table — which replaces the MBR partition scheme. GPT supports drives up to 9.4 zettabytes (theoretical maximum), allows up to 128 partitions by default, stores partition data redundantly at both the beginning and end of the disk, and uses unique identifiers (GUIDs) for each partition that prevent conflicts.

The second is Secure Boot. UEFI Secure Boot maintains a database of cryptographic signatures for trusted bootloaders. When the system boots, UEFI verifies that the bootloader's signature matches an entry in the trusted database. If it does not match — whether because the bootloader is unknown or because it has been modified by malware — UEFI refuses to execute it. This makes the boot process resistant to the rootkit attacks that plagued BIOS systems.

Secure Boot became controversial when Windows 8 required it in 2012. Linux users initially struggled with Secure Boot because their bootloaders were not in the trusted database. Microsoft eventually provided a signing service for Linux bootloaders, and most major Linux distributions now boot correctly on Secure Boot systems. However, Secure Boot can still be disabled in UEFI settings on most consumer hardware.

BIOS to UEFI: The Invisible Revolution

The transition from BIOS to UEFI happened quietly — most users never noticed. Their computers simply got faster boot times and a nicer settings interface. But underneath, the change was profound: 25 years of 16-bit legacy code was replaced with a modern, extensible platform capable of supporting hardware that the original BIOS designers could not have imagined.

Windows 11 made UEFI with Secure Boot a hard requirement, finally forcing the last BIOS-only machines out of the supported ecosystem. For Linux users, UEFI support is now standard across all major distributions. The BIOS lives on only in legacy compatibility modes for ancient hardware and in the institutional memory of anyone who spent time diagnosing problems with beep codes and jumper settings.
